# LRC-LIB-CATALOG-SWITCH: choose what opens at launch, the last library or a list of recent ones (#1290)

Closes #1290

## What changes

**For users**

- **Settings ▸ General ▸ At launch**: *Open the last library* (the default, same as today) or *Ask me*. The row only
  shows where libraries are folders you can pick (not in the browser build).
- With *Ask me*, LightCraft opens nothing at first. A window, **Open a Library**, lists the recent libraries. Each row
  shows the library's name, the folder it is in, and when it was last opened (or "Open now"). A library that can't be
  opened is greyed out with the reason: not found (moved, renamed, disconnected drive), a file rather than a folder,
  folder or catalog unreadable, or "no LightCraft library in this folder any more". The list is built **read-only**:
  nothing is locked or written in any library. So a library another program has open shows as available, and pressing
  **Open** then fails with the lock owner's message ("… is already open in another LightCraft …"), keeps the window
  up, and greys that row out. The last library is selected, or the first one that can be opened if it can't. Buttons: **Open**, **Open Another…** (the folder dialog
  of `app.openLibrary`), **New Library…** (the usual name prompt, then a location), **Remove from List**, **Quit**.
  Keyboard: ↑ / ↓ move the selection, Return opens it (unless Tab has put the focus on a button, which then acts
  itself), Esc quits. A double-click on a row opens it. If opening fails, the window stays up, says why, and greys the
  row out.
- **Alt/Option at launch**: with *Open the last library*, holding Alt (Option on a Mac) in the first 2 s after the
  window appears shows the same window once, over the library that opened. Open another library from it, or press Esc
  to keep the current one. Details under Design.
- **File ▸ Open Recent Library ▸ Remove from List ▸ <library>** forgets one entry, missing ones included. The window's
  **Remove from List** does the same. Only the path is forgotten; nothing on disk is touched.
- Files passed on the command line with *Ask me* are imported into whichever library gets chosen (the existing
  `pending_import` of the library-problem window). They now also follow a library opened another way while the window
  shows (New Library…, File ▸ Open Library…). Before this change, that path dropped them.

**For agents / control channel**

- `app.recentLibraries {remove: path}` forgets one entry. It returns an error when the list doesn't hold that path or
  `remove` isn't a string. Each listed entry now also carries `lastOpened` (ISO 8601, or `null` when not known).
- `ui.set {"settings": {"atLaunch": "ask" | "last"}}` changes the setting.
- `ui.inspect` → `libraryProblem.chooser` = `{libraries: [{path, lastOpened, available, reason}], selected,
  libraryOpen}`. Widgets: `libraryRecent:<i>`, `button:libraryOpen`, `button:libraryOpenAnother`, `button:libraryNew`,
  `button:libraryForget`, `button:libraryQuit`. Documented in `docs/control-protocol.md` → "Choosing the library at
  launch".

**Unchanged**

- `--library` and `LIGHTCRAFT_LIBRARY` still take priority over the setting, and `--memory` never asks.
- `lightcraft-cli` doesn't read the desktop `ui.json`, so it never shows the window (headless, snapshot and MCP all
  unchanged).
- The library name and parent folder in the title bar (#902): nothing to do.

## Clean-room note

The behaviour follows Lightroom Classic's startup catalogue preference ("load most recent" / "prompt me", with a
modifier key held at launch to get the prompt) as its user observes it. No Adobe text, assets, icons or code were
used, and everything was written from scratch for LightCraft.

## Design choices (small blast radius)

- **Reuses the library-problem window** (`crates/ui-egui/src/panels/library_problem.rs`) instead of adding a parallel
  mechanism. `LibraryProblem` gets one field, `chooser: Option<Chooser>`. When it is set, the window draws the list
  instead of Try Again / Choose Another / Continue Without Saving. The dimmed backdrop, `open()` through
  `app.openLibrary`, the hand-off of command-line files, the clean-up once a library opens, and the existing "Lightroom
  catalog → error" path inside this window all carry over unchanged. The failed-library window is untouched apart from
  the shared helpers it now uses (`dim`, `act`).
- **The launch decision is a pure function**, `library_problem::launch_plan(memory, flag, env, settings, default) ->
  Launch::{Open{dir, alt_asks}, Ask}`. Unit tests cover it. `apps/lightcraft/src/main.rs` calls it where it used to
  build `library_dir` by hand.
- **Alt/Option**: winit sends no modifier state before the first frame. On macOS, winit 0.30 also doesn't report a
  modifier that was already held when the window became key: `windowDidBecomeKey` sends only `Focused(true)`, and
  `flagsChanged` arrives only on a change. Windows (`WM_SETFOCUS` → `update_modifiers`) and X11/Wayland report it on
  focus. So the app watches for "Alt held during the first `ALT_SECONDS` = 2 s after the window appears" (egui input
  time). By then the last library is already open, so the window opens *over* it: `Chooser::over` records that
  library's generation. Opening another library switches (and closes the window), Open on the same library just closes
  the window, and Esc keeps it. The library is not closed, because `Session::close_library` doesn't unload the catalog
  and the UI crate can't build a fresh desktop session. The watch is skipped while command-line files are importing
  into that library, and it is armed only when nothing else chose the library (`--library`, `LIGHTCRAFT_LIBRARY`,
  `--memory` and the web host never arm it). Limitation: on a Mac, an Option key held since before launch counts only
  once it changes (press it as the window appears). This is stated in Settings' hint and in What's New.
- **Timestamps, backward compatible**: `recentLibraries` keeps its shape (a list of strings). Times go under a new key,
  `settings.recentLibrariesOpened` (path → ISO 8601 from the session clock). Earlier versions ignore the new key, files
  from earlier versions load with an empty map, and a malformed value reads as empty (`lenient`). The time is recorded
  in `LightcraftApp::library_changed`, the one place that already runs once per library opened (at launch too), and
  the map is pruned to the listed libraries. The window shows the date only. The session clock is UTC, so near
  midnight the shown day can differ from the local day.
- **Settings are saved while the list shows** (`LibraryProblem::saves_nothing`), so a removal survives Quit. The
  failed-library window and Continue Without Saving still save nothing, as before (#100).
- **Conflicts with #2672**: `AppSettings` gets two fields placed right after `recent_libraries` (not at the end of the
  struct), and `panels/settings.rs` gets one row in the General tab plus the `remove` parameter and the
  `forget_library` helper next to `recent_libraries`. Nothing in the Import tab changes.
- **Read-only listing**: each row is checked once, when the window opens (`unavailable` in `library_problem.rs`). The
  check covers: the path exists, it is a folder, the folder can be listed, it holds a LightCraft library
  (`catalog.snap` / `catalog.log`), and the catalog file opens for reading. There is no lock probe and no write, so
  listing never touches libraries on other drives, network shares or sleeping disks. Lock detection was left out on
  purpose. `catalog.lock.owner` is only a hint, often stale after a crash. A try-lock, even shared, would hold the lock
  for an instant, and another LightCraft opening that library at that moment would be refused. So a held library is
  found on Open: `switch_library` → `check_library` refuses it with `EngineError::LibraryInUse`, and the window shows
  that message and greys the row out. `listing_the_libraries_leaves_every_folder_byte_identical` snapshots every file
  (contents and modification time) in a free library, a library without lock files, a library held by another
  program, and a plain folder. It then builds the list and draws the window, and checks that nothing was created or
  changed. With the earlier lock probe put back, this test fails (`Fresh/catalog.lock` appears). At most 8 entries are
  checked. A missing or unreadable library never panics: it shows the reason.
