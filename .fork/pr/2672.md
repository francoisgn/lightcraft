## What changes (user-visible)

Before **File ▸ Import Lightroom Catalog…** starts, a window, *Import Lightroom Catalog*, asks where the catalog goes:

- **Merge into the open library "<name>" (N photos)**, with a line saying the catalog's photos, collections and edits join the ones already there. When the library is empty, the line says so instead.
- **Create a new library**. The name comes from the catalog file (`Travel.lrcat` gives "Travel", or "Travel 2" when a `Travel` folder is already there). The location is the open library's parent folder. Both are editable, and **Choose…** picks the folder. LightCraft creates and opens the library following File ▸ New Library…'s rules (`app.newLibrary`: refused in a folder that isn't empty, refused while another import runs), then imports the catalog into it. The library you leave stays in Open Recent Library.
- **Cancel** does nothing.

The window opens on *Merge* when the open library is empty, since there is nothing to merge with, and on *Create a new library* when it holds photos. The confirm button reads **Import** or **Create Library and Import**.

**Opt-out (reversible):** Settings ▸ General ▸ Library ▸ *When importing a Lightroom catalog* has two choices: *Ask where to import it* (the default) and *Always merge into the open library* (the old behaviour). The window's checkbox *Don't ask again (always merge into the open library)* picks the second. It is only available while *Merge* is chosen, and the window says where to turn the question back on. The setting is saved in `ui.json` as `settings.lightroomImport` (`"ask"` / `"alwaysMerge"`). It reads leniently: a settings file without it, or with an unknown value, asks.

**Open Library… on a Lightroom catalog** (#891) now goes through the same choice. Its offer says the next step is choosing where the catalog goes, unless the setting says to always merge, in which case it keeps today's text.

A session with no library on disk (in memory) has no folder to put a new library next to. It merges without asking, as before.

**Control channel / agents:** the app command `file.importLightroom` takes `{path?, into?: "open" | "new", name?, location?}`.
- With `into` it acts without asking. `"new"` returns the import's start plus `library: {path, name, photos}`.
- Without `into` it shows the window and returns `{asking: true, path, into}`, or merges directly when the setting says so.
- Bad params are refused before a file dialog opens.
- A catalog path that doesn't exist is refused before a library is made or the window opens.
- `location` must be a full path.

## Clean-room note

The behaviour is modelled on Lightroom Classic's own catalogue handling, as observed by its user. No Adobe text, assets or code were used; everything is written from scratch.

## Design choices (small blast radius, as agreed)

- **UI layer only.** The engine command `library.importLightroom`, `crates/engine/src/lightroom_job.rs`, `crates/ui-egui/src/lightroom_import.rs` and the import itself are untouched, so the open PRs working there (#2599, #2168, #1735, #2051, #1232, #1014, #2412) don't conflict. The window only decides which library is open when `library.importLightroom` is dispatched.
- **One new module, `crates/ui-egui/src/lightroom_destination.rs`.** It holds the decision logic (`decide`: setting × library on disk/in memory × photo count × `into`, a pure function with unit tests), param parsing, default name/location, the window body, confirm, and the keep-open-on-error rule. `menus.rs` (`file.importLightroom`), `panels/dialogs.rs`, `control.rs` (`ui.dialog.confirm`), `state.rs` (setting + `Dialog::LightroomDestination`) and `panels/settings.rs` (the Settings row; `free_name` made `pub(crate)`) only gain small hooks.
- **The new library goes through `app.newLibrary`**, so its rules and error messages stay in one place.
- **The window stays open after an error** (a folder that isn't empty, an invalid name) so it can be corrected, with the error as a toast.
- **No merging into another library by accident.** If another library was opened while the window was up (an agent, the control channel), *Merge* is refused ("…nothing was imported") and the window closes. It records `Session::library_generation`, as Move Photos does.
- **Choose… calls the folder service synchronously.** This is the same as the Export dialog's Choose….
- **i18n.**
  - The two `tr_format!` messages are translated in all 17 `*-formats.json` catalogs (required by the build). Plural suffixes follow the existing `{:.0}` practice.
  - The plain strings are translated in `fr.json`. Other languages show English until translated; gaps are reported, not failed.
